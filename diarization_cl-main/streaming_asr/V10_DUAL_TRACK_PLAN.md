# v10 双轨流式方案与最小实验计划

状态：旧 E1 预览在 LLM 后对照中失败；8735 改为两遍离线对照，在线会议架构仍待实现  
日期：2026-09-16  
基线：`v7 + auto FRCRN + DeepSeek LLM`

在线主 ASR 选型已冻结为 **Paraformer-Streaming**。SenseVoice 不进入主链路；
Fun-ASR-Nano 只承担异步端点二遍定稿，不能阻塞在线草稿。

### 2026-09-16 用户反馈后的修正

用户提供的 v9、v10 都是 LLM 纠错后结果。旧 v10 的文字和短答归属均明显退化，
不能以“还没做 LLM”解释。原提示词禁止改错别字，反复校正也不能补回声学证据。
方法名中的 `+llm+llm` 与 `+llm+llm+llm` 表明轮数不同；后续验收固定相同一轮，
但轮数差异不否定此次退化反馈。

- 连续 ASR 缓存不再由 speaker 滑窗切开；同一段音频不按重叠 speaker 区间重复解码。
- speaker 区间只能作为归属证据，不能作为唯一 ASR 断句依据。窗口重叠不等于真实抢话。
- 在线第一遍仅输出 draft；VAD 端点或有长度上限的语音块进入异步高质量重识别，
  原始音频索引、两遍文本、字级对齐和 speaker 证据共同进入增量 LLM。
- 没有声学时间锚时不允许 LLM 猜出已确认边界；短答证据不足时保留 unknown。
- 会后再用全局上下文定稿；在线修订与会后版本分别保存、分别验收。

当前 lane 只将第二遍替换成冻结 v7 离线参考，验证草稿/参考输出分离和质量回退。
这不证明在线端点二遍可行，也不代表 v10 分离能力提升；仍需真实端点、对齐、
在线 Tracker、有界队列及 30–60 分钟多人留出集。04320 仅做短答回归。

本机当前没有 `fa-zh` 强制对齐模型，不能把 Nano 整段文本可靠拆回声学时间轴。
同时加载 VAD、CAM++、Nano 和 Paraformer-Streaming 后，实测服务工作集约 6.35 GB、
私有内存约 12.69 GB；正式方案必须做模型阶段调度并测 60 分钟内存曲线。

## 1. 已复核的当前事实

1. `V10_HANDOFF.md` 中记录的五个关键文件 SHA256 与当前文件一致。
2. 当前 `8735` 是整文件上传链路：转码、整文件环境检测、可选整文件 FRCRN、离线说话人
   分段、逐段 ASR，最后才返回 lane 结果。NDJSON 只用于传进度，不代表音频或识别是流式的。
3. 当前说话人模型是 CAM++，不是 ECAPA-TDNN；现有 v7 以滑窗嵌入和 AHC 做整段聚类，
   没有跨数十分钟持续更新的在线身份状态。
4. 当前 Fun-ASR-Nano 适配器只返回整段文本。其本地 README 明确将“返回时间戳”列为
   TODO，不能用它实现基于 token 时间戳或 CTC blank 的在线锁定。
5. 本机缓存的 Paraformer 是离线模型。README 中虽有流式模型调用示例，但对应的
   `paraformer-zh-streaming` 模型目前不在本机，不能把文档示例当作已具备的能力。
6. 当前 FRCRN 对整段音频一次前向，属于离线前处理。使用预先对整场会议降噪的文件做
   回放会偷看未来，不能据此报告在线延迟或在线效果。
7. 当前 LLM 是用户另行触发的整段后处理，提示词限定“双人奶茶店对话”和 speaker 0/1。
   它既不支持多人，也没有增量 revision 契约，尚未达到 PRD 所要求的正式在线阶段。

## 2. 架构决定

采用“双轨异步”作为 v10 的总体结构，但不直接接受示例中的模型、阈值和继承规则：

```text
16 kHz 单声道音频 + 单调 sample_index
        |
        +--> 在线 ASR --> 带时间范围的 draft/final token
        |
        +--> 在线 VAD --> 合格声纹证据 --> Speaker Tracker
                                              |
ASR token + VAD 区间 + speaker evidence ------+--> 时间线融合
                                                    |
                                                    +--> 在线增量 LLM 修订
                                                    +--> 实时展示/断线重放
                                                    +--> 会后全局聚类与 LLM 定稿
```

两个轨道只通过同一个音频时钟对齐。时间的主键使用从会议开始累计的 16 kHz
`sample_index`，展示时才转换成毫秒，避免墙上时钟漂移和浮点累计误差。

在线输出采用追加式 revision 日志。每次修订至少包含：

```text
meeting_id, revision_id, replaces_revision_id, state
start_sample, end_sample, text, speaker_id, confidence
asr_evidence_ids, speaker_evidence_ids, reason, created_at
```

`state` 只需要三种：`draft`、`endpoint_final`、`post_meeting_final`。重连时从客户端最后
确认的 `revision_id` 继续重放；原始 ASR、声纹证据和 LLM 请求/响应均不可被覆盖。

## 3. 对建议细节的取舍

### 直接采纳

- ASR 与 diarization 异步执行，speaker encoder 不能阻塞文字首稿。
- 只有较长、较干净的语音才允许更新 speaker centroid。
- 新身份先进入候选态，不能由单个异常 embedding 立即创建 speaker。
- 在线只冻结安全前缀，尾部允许修订；会后另做全局定稿。
- token/字时间范围与 speaker 活跃区间按重合证据融合。

### 作为待校准变量

- `160--200 ms` 步长、`80--160 ms` lookahead。
- 声纹更新最短时长 `1.2 s`、短答界线 `0.8 s`。
- cosine 阈值 `0.65--0.72`、连续确认次数 `>= 3`。
- EMA 的 `alpha`。

这些值都依赖模型 embedding 空间、噪声、麦克风距离和会议语料，必须只在调试集校准，
冻结后再跑留出集。

### 明确不采纳

- **短答一律继承前序 speaker。** 在“甲长句 -> 乙回答‘对’”中必然把乙标成甲。短答
  可以不更新质心，但仍应尝试匹配已有稳定 speaker；证据不足时输出 `unknown`，让后续
  声学证据或 LLM revision 修订。
- **把同一连续 VAD 段的三个重叠窗口当作三次独立确认。** 它们高度相关，容易把一次
  咳嗽或变声晋升为新身份。新 speaker 晋升优先要求跨独立 speech region 重复出现；
  单个长 region 只能形成 probation 身份。
- **直接使用给定 EMA 公式。** `max(0.9, 1-1/n)` 在样本很少时也只给新证据 10% 权重，
  在样本很多时又趋近完全冻结。先比较固定 EMA、质量加权均值和有上限的累计均值。
- **LLM 自由生成时间边界。** LLM 只能选择声学 anchor、合并相邻证据或提出
  `needs_review`；没有声学 anchor 的新边界不能进入已确认结果。

## 4. 可证伪假设

| 编号 | 假设 | 反证条件 |
|---|---|---|
| H1 | 双轨异步可降低首稿延迟，且不会因 diarization 排队阻塞 ASR | 关闭 speaker 轨与开启 speaker 轨相比，ASR 首稿 P95 增加超过 100 ms，或 ASR 队列持续增长 |
| H2 | “短段不更新、仍可匹配”比“短段继承前人”更能保留短答身份 | 04320 和长会议短答集上，短答归属准确率没有提高，或 DER 明显恶化 |
| H3 | 候选池能减少幽灵 speaker，且不压掉真实晚入会者 | 新身份 precision 无改善，或真实新说话人的确认延迟 P95 超过 8 s |
| H4 | 稳定前缀锁定能降低界面抖动而不增加不可修复错误 | 每分钟字符回滚没有下降，或冻结前缀错误率高于未锁定方案 |
| H5 | 有声学约束的在线 LLM 能恢复短答轮次，且不制造非法时间边界 | LLM 后短答召回无提升，或出现无 evidence reference、越界、倒序时间段 |
| H6 | 会后全局重聚类能改善身份连续性，同时完整保留在线历史 | 会后 DER/身份切换不优于在线结果，或 revision 无法还原在线展示 |

## 5. 最小实验矩阵

按顺序执行；前一项不过闸门，不进入后一项。

| 实验 | 只改变什么 | 数据 | 主要输出 | 通过条件 |
|---|---|---|---|---|
| E0 冻结基线 | 不改算法，保存 v7/v9 的 FRCRN、raw、LLM 前后证据 | 04320、旧可信集、长会议调试集 | 完整可重放记录 | 04320 结果可复现；v7/v9 均有 LLM 后结果 |
| E1 ASR 能力探测 | 在线 ASR 候选、chunk/lookahead；关闭 diarization 与 LLM | 限速 1x 文件回放 | partial/final token、时间范围、延迟、CER、RTF | 真正只读已回放音频；有可用时间范围；首稿 P95 <= 1.0 s；持续 RTF < 1 |
| E2 Tracker | 固定同一 ASR；比较前序继承、短段匹配、候选池 | 04320 + 多人调试会议 | DER、短答归属、新人确认延迟、幽灵数 | 短答不低于 v7+LLM 回归；候选池不增加漏人；阈值只由调试集确定 |
| E3 融合与 revision | 固定 ASR/Tracker 输出，只测事件合并、尾块、重连 | 合成事件 + 会议回放 | 确定性 revision 日志 | 同一事件流输出字节级一致；断线重连无丢失、重复或旧 revision 复活 |
| E4 在线全链路 | 加入增量 LLM 与真实队列 | 04320 + 多人调试会议 | 在线产品指标 | LLM 不改无依据边界；无全历史重写；积压可恢复 |
| E5 冻结验收 | 参数、提示词、模型全部冻结 | 独立 30--60 分钟多人会议 | 在线报告 + 会后报告 | 达到第 6 节全部硬门槛；不得用会后结果替代在线结果 |

E1 固定使用 Paraformer-Streaming 作为在线首稿，并比较是否增加 Fun-ASR-Nano 在 VAD
端点做异步二遍定稿。后者只有在 GPU 负载、端点延迟和 CER 同时可接受时保留。不能对
当前 Fun-ASR-Nano 强行补伪 token 时间戳。

04320 的首次 CPU 探针结果（未降噪、无 VAD/LLM/speaker，仅验证流式能力）：

```text
chunk: [0, 10, 5]，每次输入 600 ms，尾块 50 ms 正确 is_final
音频长度: 13.85 s，共 24 chunk
纯推理 RTF: 0.1039
单 chunk 推理: P50 61.3 ms，P95 68.2 ms，max 95.9 ms
最大积压: 0.5 ms
首个非空 chunk 音频终点: 4200.0 ms
首个非空结果上屏: 4268.4 ms（该 chunk 到达后 68.4 ms）
```

该结果证明 CPU 上具备短时实时处理余量，但不等于完成 E1：尚缺 30--60 分钟持续回放、
有声起点延迟、CER 和内存增长。原始逐 chunk 拼接出现“果果”“没没有”“有有吗”等
边界重复，不能直接展示；下一步需验证稳定前缀或可回滚 revision，而不是用字符串规则
盲删重复字。当前模型没有 token 时间戳，时间证据粒度暂为 chunk 范围。

## 6. 验收标准

### 证据与正确性硬门槛

- 04320 中“没有吗？”保持独立短答，不与“对，然后……”合成同一人长轮次。
- 每个 `endpoint_final` 和 `post_meeting_final` 都能追溯到 ASR 与 speaker evidence。
- 时间段不得倒序、越出已接收音频或凭 LLM 文本猜测生成；无法确认时使用
  `unknown/needs_review`。
- 多人数量不设上限常量；重叠发言不能被静默强制成单 speaker。第一阶段若无可靠重叠
  检测，只能标记 `overlap_unknown`，不能声称已解决重叠。
- 在线指标只使用当时已到达的音频和上下文；预先整段 FRCRN 的结果只计入离线基线。

### 在线系统硬门槛

- 首个文字草稿 P95 `<= 1.0 s`；VAD 端点后的 `endpoint_final` P95 `<= 2.0 s`。
- 连续 60 分钟回放的整体处理 RTF `< 1.0`，队列积压不随会议时长单调增长。
- 暂停/恢复与尾块 flush 后不丢字；模型异常要产生可重试事件，不能丢原始音频索引。
- 浏览器重连后，从最后确认 revision 继续，最终状态与未断线客户端一致。
- 第 10--60 分钟 CPU 内存、GPU 显存、speaker/candidate 数和 revision 缓存均有上界；
  具体上限在 E1/E3 测得空载基线后、运行 E5 前冻结。

### 效果报告

- LLM 前：CER、DER、边界 precision/recall、短答召回、身份切换、幽灵/漏 speaker。
- LLM 后：文本准确率、speaker 归属、短答独立率、非法边界数、待核验率。
- 在线：首稿/端点/LLM revision 延迟 P50/P95/P99、RTF、最大积压和恢复时长。
- 会后：全局定稿的同类指标及其相对在线结果的变化，另附 revision 可追溯率。

## 7. 实施顺序

1. 先冻结 v7 基线副本和证据，不改 `claude_a2_v7_v8.py`。
2. 获取真实多人调试会议和独立留出会议并完成最小标注；没有留出集时不调阈值。
3. 只实现 E1 所需的 1x 文件回放与 ASR 能力探测，验证模型是否真的流式且有时间范围。
4. E1 通过后才实现最小在线 Tracker；复用现有 CAM++ 作为第一个候选，不先换 ECAPA。
5. Tracker 通过后再加入 revision 日志、重连和增量 LLM。
6. 最后实现会后全局重聚类与定稿，并在冻结留出集一次性验收。

8735 的 v10 E1.1 lane 先对整段音频做连续 Paraformer-Streaming 因果回放，再复用冻结
v7 产生离线对照文本，避免按重叠 speaker 段重复识别，也不再把流式草稿标成最终稿。
它仍不是双轨在线会议实现：没有在线 Tracker、真实 VAD 端点、token 时间戳或增量 LLM。
页面保留正式 LLM 校正入口，同条件比较时只能执行一次校正。

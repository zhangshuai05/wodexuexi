## 2. §核心：K 上限修复的实际代价

`v11._candidate_clusters(E, max_speakers=MAX_SPEAKERS)` 的默认值在 **def 时**
绑成 `v11.MAX_SPEAKERS`=4，`_v11_window_params` 改模块变量改不动它。
修法：`v12.diarize` 两处调用点显式传参（主窗 + 救援），`v11` **零改动**。

### 2.2 代价（12 场实测）

**⚠️ 先读这条基准说明，否则下面的数字会被误读。**

第一次跑步骤 A 时（`e62fdbb`），探针的 base **尚未修正**（cap 还是 4），
所以得到"11 保持 / 1 有差异"。`11790cf` 修正探针 base 后**重跑**，
探针 base 与生产同源，结果变成"**12/12 保持**"。

**后者是同义反复**（修正后两边用同一套候选构造，本来就该一致），
**不是**"修复无代价"的证据。真正回答"修复的代价"的是**第三种对比**：

| 口径 | k | 归属率 | 含义 |
|---|---:|---:|---|
| 探针**旧** cap=4 | 4 | 78.7% | 修复**前**的生产行为 |
| 探针**新** cap=10 | 5 | 90.7% | 修复**后**的生产行为 |
| 生产 `diarize`（修复后） | 5 | 90.7% | 与上一行一致（同源，必然） |

⇒ **修复把 `S_R004S01C01` 的 k 从 4 提到 5，归属率 +12.0 pts。**
这是修复的**实际效果**，与"两边是否一致"是两个问题。

其余 11 场：三种口径下 k 相同、段表逐位相同、归属率相同 —— 修复**零影响**。

**结论**：`977fc6b` 的效果是 **1 场改善、11 场无变化**。
（不是"12 场都无变化"——那个说法来自同源对比，无效。）

## 3. ★ 核心发现：base 系统性欠分割，A 表现为条件性兜底

### 3.1 base 的失败模式：**系统性欠分割**

**先看真值。** dev 12 场的 RTTM 真值说话人数几乎恒定（**5–6 人**，中位 6）：

```
base k == 真值人数 的场次：1/12
base k 与真值的差： [5, 2, 3, 2, 4, 4, 4, 4, 0, 3, 3, 3]
```

**12 场里 11 场欠分割，平均少 3 人。** 这不是"分得较多"，是系统性偏低。

### 3.1a ⚠️ 两条**待验证假设**（不许当结论引用）

"欠分割"这个**观察**是硬的（`base k` 与 RTTM 人数逐场可复算）。
但由它推出的下面两条**都是假设**，本轮**未验证**：

1. **"真值人数就是应选 K"** —— **不成立或至少未证明。**
   K 可能同时承担**说话人身份数量**与**时间边界锚点数量**两个角色
   （该假设见 `milestones/c1_v13_ab_eval_20260924/README.md` 的"待优先验证"一节）。
   若如此，最优 K 经常大于真实人数，**不能**拿 RTTM 人数当 K 的目标值。
   本报告只用 RTTM 人数说明"base 偏低"，**不**主张"base k 应等于真值人数"。
2. **"份额门是最终错误根因"** —— **只是候选准入层面的观察。**
   实测的是"base 的合格上界被哪道门卡住"（份额门单独 3 场 / 两道同时 8 场 /
   窗数门单独 0 场）。这是**候选准入**的事实，不等于"改这道门就能修好欠分割"：
   过分割的代价未度量、簇纯度未测、且与 base 质量本身正相关（+0.452）。
   见 §3.4 与 §9.2 的实验设计。

**措辞纪律**：引用本节时，"欠分割"可写为事实；
"K 应等于真值人数"与"份额门是根因"必须写成**待验证假设**。

欠分程度与 A 的增益相关（`corr = +0.621`）：

| 欠分 | n | Δ 均 | 逐场 Δ |
|---|---:|---:|---|
| 0–2 | 3 | **−5.5** | −4.7, −9.2, −2.7 |
| 3–5 | 9 | **+16.2** | +48.0, +22.9, 0.0, +5.6, +16.0, +50.9, +0.9, +1.7, 0.0 |

⚠️ 这个 0–2 / 3–5 分组与 §3.2 的 `k≥4 / k≤3` 分组**是同一组场次**——因为 base 的
选中 k 几乎恒等于合格集合上界（§3.1b），而真值人数恒定，两者互为镜像。
**它们是同一个变量的两种写法，不构成两个独立的解释。**

### 3.1b 合格集合的上界卡在哪道门

12 场的 base 选中 k 与**合格集合上界**逐个吻合（唯一例外 `M_R003S05C01`：
上界 3 却选了 2）：

```
合格集合上界： 1 场=0   6 场=2   2 场=3   2 场=4   1 场=5
base 选中：    全部 = 该上界
```

合格判定有**两道**门（都在 v11，实际生效）：

```
eligible = (min(sizes) >= MIN_CLUSTER_WINDOWS)       # 窗数门 = 4
           and (min(sizes)/n >= MIN_CLUSTER_SHARE)   # 份额门 = 0.015
```

**逐场查清"上界被哪道门卡住"（12 场全样本）**：

| 卡点 | 场次 | 说明 |
|---|---:|---|
| **窗数门单独** | **0** | 12 场里**没有一场**是单独被它卡住的 |
| **份额门单独** | 3 | `S_R004S02C01`、`S_R004S04C01`、`L_R003S03C02` |
| **两道同时** | 8 | |
| 无（无更高候选） | 1 | `L_R003S01C02`（上界 0） |

⇒ **在候选准入这一层面上**，主导卡点是份额门 `MIN_CLUSTER_SHARE=0.015`，
不是窗数门。

**限定**：这是"合格集合的上界被哪道门算出来"的**观察**，
**不等于**"份额门是欠分割的最终错误根因"。改门限能否修好欠分割，
需要 §9.2 的实验（含过分割代价与簇纯度），本轮未做。见 §3.1a 与 §3.4。

这有一个直接的方法论后果：**单独扫窗数门会得出"门限无效"的假结论** ——
已实测，窗数门取 2/3/4/6/8 时三场结果**完全相同**。敏感性实验必须**双门联合扫描**。

**关于欠分割的机制**（未分离验证，仅记录观察）：真值 5–6 人、主窗 281–585 个，
按 4 窗门限本应容得下 5–6 簇；实际被份额门卡住，说明**多人在嵌入空间被判成同一簇**
（导致某些簇过大、其余簇过小），而非单纯的"碎簇过多"。这是候选解释，**未验证**。

### 3.2 A 的增益与"base 处于哪个 k 区间"相关

```
base k >= 4  →  A 下降     3/3 场全部下降（均 -5.5 pts）
base k <= 3  →  A 不下降   9 场中 7 提升 / 2 持平 / 0 下降（均 +16.2 pts）

corr(base主指标, Δ) = -0.925   （且两组内部各自仍 -0.930）
corr(A k,        Δ) = +0.029   ← A 选多少 k 几乎不预示结果
```

逐场明细（k<=3 组的 9 场）：

| 场次 | base k | Δ |
|---|---:|---:|
| M_R003S01C01 | 2 | +0.0（持平） |
| S_R004S04C01 | 2 | +0.0（持平） |
| S_R004S02C01 | 2 | +0.9 |
| S_R004S03C01 | 2 | +1.7 |
| M_R003S02C01 | 2 | +5.6 |
| M_R003S04C01 | 2 | +16.0 |
| L_R003S03C02 | 3 | +22.9 |
| L_R003S01C02 | 1 | +48.0 |
| M_R003S05C01 | 2 | +50.9 |

k>=4 组 3 场全部下降：`L_R003S04C02` −9.2、`L_R003S02C02` −4.7、`S_R004S01C01` −2.7。

**第三行是关键**：A 的判据（阈值 0.6）选出的 k 是多少，对结果几乎没有信息量。

### 3.3 结论（措辞要保守）

> **在本探针口径与 dev 这 12 场样本内**，A 表现为**条件性兜底**：
> base k≤3 的 9 场中 7 场提升、2 场持平、0 场下降；
> base k≥4 的 3 场全部下降。

**这不能推出：**

* ❌ A 是**普适** K 判据 —— 只证了它在 base 塌陷的场次上有效，
  而"哪些场会塌"本身仍是未解释的变量
* ❌ base 在 k≥4 的场次上**已经分对** —— 我不知道真人数量，
  `k≥4` 只说明"分得较多"。**"已分对"是未经真值验证的断言，本报告不再使用**
* ❌ **门限已被证明过严** —— 无论窗数门还是份额门。见 §3.4

### 3.4 门限的现状：只是待检验的候选解释，且卡点在**份额门**

事实：base 的合格上界被两道门卡住（见 §3.1b 的逐场表），
其中**份额门 `MIN_CLUSTER_SHARE=0.015` 是主导**（单独卡 3 场、与窗数门同时卡 8 场，
**单独被窗数门卡住 0 场**）。base 的选中 k 几乎等于该上界。

但这**不足以**说门限过严，因为缺三件事：
1. **没有过分割的代价度量** —— 放宽门限会让 k 变大，那些新增簇有多少是人、
   多少是碎簇？`Δ未匹配` 是个弱代理（`corr(Δ主指标, Δ未匹配)=+0.242`），不够。
2. **缺"簇纯度"** —— 需要真值才能判断新增簇是否对应真人。
   真值人数**可得**（RTTM，dev 12 场为 5–6 人），但纯度需要窗级对齐，尚未做。
3. **混杂未分离** —— 上界与 base 主指标本身正相关（+0.452），
   且门限同时影响 base 与 A 的候选空间，当前数据无法隔离。

故门限**只是**一个待检验的候选机制。实验设计见 §9.2。
**注意**：不要只盯 `MIN_CLUSTER_WINDOWS` —— 逐场证据显示主导卡点是份额门。

### 3.5 两个负例的性质不同

| 场次 | base | A@0.6 | 性质 |
|---|---|---|---|
| `L_R003S04C02` | k=4, 84.0% | k=10, 74.8% | 老反例，两个基准下都成立（-9.2） |
| `S_R004S01C01` | k=5, 90.7% | k=6, 88.0% | **新负例**：base 修好后 A 才落后（-2.7） |

正是 `MIN_CLUSTER_WINDOWS=4` 会拦掉的碎簇。

### 9.1 前置事实：卡点不止一处，且已定位

`_candidate_clusters` 的合格判定有**两道**门（都在 v11，实际生效）：

```
eligible = (min(sizes) >= MIN_CLUSTER_WINDOWS)      # 窗数门，= 4
           and (min(sizes) / n >= MIN_CLUSTER_SHARE)  # 份额门，= 0.015
```

**已实测（三场缓存，零模型）**：单独扫窗数门 2/3/4/6/8 —— 结果**完全相同**。
因为真正的卡点常常是**份额门**：

```
L_R003S03C02  n=387
  k=3: min=9  窗数门过(9>=4)  份额门过(0.0233>=0.015)   → 合格
  k=4: min=4  窗数门过(4>=4)  份额门否(0.0103<0.015)    → 被拦
```

⇒ **敏感性实验必须双门联合扫描**，只扫窗数门会得出"门限无效"的假结论。

### 9.2 门限敏感性实验的设计

**要回答的问题**（二选一，分别设计）：

* **Q1（描述性）**：把两道门限松弛到不同水平，base 的选中 k 与归属率如何变化？
* **Q2（规范性）**：是否存在一组门限使 base 在**欠分割**上改善，且在
  **过分割**上不付出代价？

**必测的对照量（缺一不可）**：

| 量 | 为什么必须 |
|---|---|
| 选中 k 与**真值人数**的差 | 欠分割的直接度量。真值可由 RTTM 取（已确认可得，dev 12 场真值 **5–6 人**） |
| 新增簇的**纯度** | 区分"放宽门限分出真人"与"分出碎簇"。无此量则无法判断过严/过松 |
| 归属率（主指标） | 现行口径，保持可比 |
| **未匹配率** | 碎簇的直接信号（弱代理，`corr=+0.242`，仅作辅助） |
| 每场的**簇尺寸分布** | 判定卡点在哪道门 |

**必须排除的混杂**：

1. **双重作用**：门限同时影响 base 的候选空间与 A 的候选空间。
   若要问"base 的选 K 会不会更好"，实验**不得**同时动 A。
2. **与 base 质量的相关**：上界与 base 主指标本身正相关（+0.452），
   分层分析会混杂。需报告**逐场**，不只均值。
3. **样本量**：12 场，**任何分组结论都受 n 限制**（本轮两次错判都源于此）。
   真值人数恒为 5–6，无法做"人数 × 门限"的交互分析。

**预期与反例（预先记录，防事后叙事）**：

* 若"放宽即改善"成立，则应在**所有**欠分割场次上改善 —— 否则机制不成立。
  已有一个**预登记的反例候选**：`S_R004S01C01` 真值 5、base k=5（**欠分 0**），
  放宽门限只会让它过分割。
* 若"放宽无改善"，则本轮"门限过严"的候选解释**被证否**，base 的欠分割来自
  嵌入空间本身（同一人被切成多簇且各簇都小），而非门限。

**规模**：仅用 dev 12 场（不做迁移结论）。零模型（读已建的 12 场生产门缓存）。
**不要**动 `claude_a2_v11.py` 的常量 —— 用上下文管理器或探针内 monkeypatch 扫描。

## 1. 我们在做什么

**目标（spec §4.4）**：回答一个可证伪的问题 ——

> 固定现有 CAM++ 192 维嵌入，换成**真正的 VBx**（贝叶斯 HMM + PLDA 先验，从零 EM），
> 在调参集上的**错答率**能否下降 ≥ 1 个点？

- 降 ≥1 点 ⇒ 假设成立，**立项写 VBx 的 EM**
- 降 <1 点 ⇒ **证伪**，转去对齐文献口径，不再在自制管线上打磨

但在写 VBx 之前，先做一个**便宜得多**的前置（本线正在做的）：

> **修好仓库里唯一现成的后端对照台，看正则化 LDA 有没有东西。**

理由：台子是现成的、几十分钟能出数；VBx 的 EM 是几十倍工作量。**若"错答对嵌入空间
不敏感"，VBx 也不必写** —— 用最小成本换掉最大不确定性。

**主指标**（spec §2.1）：**句级说话人归属率**，按句平均，**弃权计入分母**，
匈牙利**双射**映射到真值人，评价对象是 **`clean` 桶**（无重叠句）。
`clean = 1 − 弃权率 − 错答率`，但**后两者必须分别卡上限**（错答 ≤8%、弃权 ≤2%）。
**DER 已降为诊断指标**，不是验收指标。

## 3. 当前卡在哪

**卡在一句裁决上，不是卡在技术上。** 三件事，按优先级：

### 卡点 1（已裁决 2026-10-13）：`unmapped` 单列

Task 4 的实现者实测报告：`wrong = 1 - per_sentence - abstain` **算术上恰好等于
`unmapped + 真·答错`**，也就是 **`unmapped` 被折进了错答数**。

- 他量了量级：`unmapped` 在几乎所有 (场次, k) 上是 **0**，只在 k=8 时 **0.042–0.049**
- 他**有意保留**了折入写法，理由：`unmapped` 对读者也是"看不见的"，
  且加第五个键会与当时定的四键形状冲突

仓库自己的 `probe_sentence_attribution.attribution` docstring 明确区分过两者：

- `abstain` = 该句**没有任何预测覆盖**（显式缺失，读者看得到）
- `unmapped` = 该句**有**预测，但那个标签没被匈牙利映射到任何名字
  （映射容量不足 / 簇分裂造成）—— **明确不是弃权**

**裁决：单列，同时保留合并后的产品指标。**

```
per_sentence + wrong + unmapped + abstain == 1     ← 四类恰好加满 1
产品验收的归属错误率 = wrong + unmapped             ← 继续受原 ≤8% 错答预算
```

`is_unmapped` 的定义含 `not is_abstain`（两者互斥），而 `mapped == truth`
在 `mapped` 为空串时恒假 ⇒ 上面的恒等式成立，且 `attribution_error` 恰好
等于 `1 - per_sentence - abstain`。**拆开只增加诊断分辨率（混人 vs 过分割），
不放松验收** —— 两个字段都在同一个预算里。

已实现（`sentence_metrics` 四类 + `attribution_error`），并加了红验证过的断言：
把 `unmapped` 折回 `wrong` 会让四类之和的断言立刻红。

### 卡点 2（存在混杂，影响方向待验证）：`SLIVER_MARGIN` 尺度混淆

细化里的阈值 `v12.SLIVER_MARGIN = 0.18` 是在**原始 192 维余弦尺度**上标定的绝对阈值。
LDA 把判别方向拉长后，margin 尺度整体放大，于是**所有 LDA 臂都系统性地少吸碎段**。

**独立复现的实测**（4 场 × k=3）：

| 臂 | margin p50 | <0.18 占比（=吸碎段量） |
|---|---:|---:|
| `none`（原始） | 0.195–0.232 | **0.32–0.45** |
| `c8_cos` | 0.50–0.69 | 0.13–0.18 |
| `c8_euc` | 1.35–2.70 | 0.045–0.09 |

**关键：归一化治不好它。** 归一化对 `_cos` 是**空操作**（它本来就单位范数），
对 `_euc` 也只把 0.045 抬到 ~0.13，**仍到不了 `none` 的 0.32–0.45**。
根因是**阈值本身不随空间不变**，不是范数。

**影响方向待验证（不要写成"净值偏保守"）**：少吸碎段是**已观测**的，但碎段吸收
净有益还是净有害**需要对照才能定**。早期版本据此断言"净值被压低 ⇒ 假阴性"，
那是把"混杂存在"当成了"方向已知"。**正确表述：存在已知混杂，影响方向待验证** ——
读 `auto` 臂结果时须计入，但不得据此把阴性结果解释成保守。

**已裁决**：不在任务里修（修它要么动冻结的 `SLIVER_MARGIN`，要么发明逐臂重标定，
两者都超范围）。**动作 = 在 Task 5 产物的 `note` 里写明**：
"细化阈值 0.18 在原始空间标定，LDA 臂因此系统性少吸碎段，**存在混杂，
影响方向待验证**。"

### 坑 A2：**拿主检出的数去对 worktree 的数**（已过期，2026-10-13 后两处一致）

**合并前**两个检出的测试数不同（主检出 154/0 vs worktree 156/3），差异全是环境
（见坑 W1/W2/W3）。拿错基线会把"环境性失败"误读成"我弄坏了 3 个测试"。

**合并后**（`worktree-backend-spike` 已 ff 进 main）：两处都是 **160 passed / 0 failed**
—— worktree 的 3 条环境性失败在主检出上本就不发生（VAD 模型目录与 CRLF 只存在于

坑 W1/W2/W3 依然会在**任何新 worktree** 里复现。

### 坑 A3：**以为 `probe_ab_dev.score()` 返回三桶**

`score()` 只返回 `overall` 派生的 6 个键（`per_sentence` / `duration_weighted` /
`abstain` / `unmapped` / `n` / `n_sentences`）。`clean` / `overlap` 桶**只在
`probe_sentence_attribution.attribution()` 的返回值里**，`score()` 把它丢掉了。
**计划 Task 4 的 brief 就是这么错的**（写成 `assert "clean" in s`），已由裁决改成
新写一个 `sentence_metrics()` 重建取桶路径。
**不要改 `AB.score` 本身** —— 它的调用方全是 `**AB.score(...)` 解包，加键会静默
改掉它们的产物 schema。

### 坑 A4：`.gitattributes` 的 `* text eol=lf` 会写坏二进制

任何 `git add -A` 都可能让 png/npz 被 eol 过滤清洗（实测 png 少 25 字节）。
**逐个路径精确暂存。**

### 坑 A5：**测试断言恒真**（本线连续踩了三次）

这是本线最贵的坑。三次实例：

1. Task 2 首版测试用 `labels = np.zeros(...)` ⇒ `k=1` ⇒ `real_path_labels` 走**早退分支**，
   `ft is times` 与 `level == "2s-only"` **两个断言恒真**，对它要测的新代码**零覆盖**。
2. 我（controller）给 Task 2 建议的维度断言 `vectors.shape[1] == rvectors.shape[1]`
   **也是恒真的** —— `Transform.__call__` 是 `(X - mean) @ weights`，输出宽度只由
   `weights` 决定，与输入宽度无关（输入 192 列、输出恒 14 列，两边一样）。
   更糟的是它在测试里**本地**构造 `rvectors`，源码改回 `rE` 也改不动它比较的两个值。
   **实现者顶回来是对的。**
3. Task 3 的 autok 覆盖：**数选择器调用次数也不够** —— 两臂变体数相等，
   "选择器被挪到 true 臂"照样通过。必须**绑值**（记下 `pick_unlocked` 实际返回的 k，
   与产物里的 `k_used` 逐值比对）。

⇒ **规矩：每写一条断言就问"哪个合理回归能让它保持绿"。答不出来就说明它没覆盖。**
验证方法：**真去改源码让它红**，把命令和输出写进报告。做不到就如实说做不到。

### 坑 A6：**静默丢弃场次/整行**

"少了几场"和"本来就这么几场"在产物里长得**一模一样**。本线修了两处同类问题：
「无 refine 缓存的场次」原本静默 `continue`，现在显式告警；
`len(emb) < 2 or len(effective) < 2` 原本丢掉整行，现在逐变体落存根行（带 `skip` 理由）。

### 坑 A7：**两条臂不同构**

对照实验里，若一条臂走了细化、另一条没走，或一条臂在 LDA 空间、另一条在原始空间，
测出来的差值里混着**别的东西**。本线两次踩到：
- Task 2：`rE`（192 维原始）配 LDA 空间的锚点（15 维）⇒ `E @ anchors.T` 直接
  `ValueError`，**每个 LDA 臂全崩**。而崩掉的行走的是 `{accuracy: null}` 存根格式，
  **极易被读成"后端臂无数据"**。修法：细化窗过**同一个** `fit`（`rvectors = fit(rE)`）。
- Task 3：`_euc` 变体必须跳过 autok —— `build_unlocked` 内部
  `linkage(E, method="average", metric="cosine")` 是**写死的**，
  让欧氏空间的输出经它选 k = 拿余弦 silhouette 评价欧氏空间。
  **不要给它加 metric 参数**（会动生产共用实现），跳过即可。

### 坑 A8：**对照实验台的默认设定可能对某条臂特别有利**

`probe_backend_sweep.py` 原来的训练池是"除目标场外全部 20 场"，脚本头自述
"是对后端最有利的设定"。收口到 dev-only 后池变小、噪声变大 —— **这是本线的自觉代价**，
不是缺陷。实测代价：`classes` 轴在 dev 上**基本无分辨率**（见 §7）。

## 7. 本线已确证的实测结论（可引用，但注意口径）

**训练池收口到 dev-only 后的代价**（与 `lda_fit` 同构的 leave-one-out 复现）：

- 池 **12 场、16 个类**（类 = `(身份组, 说话人)`），`classes` 四档**全部 12/12 场可 fit，不缺格**
- **`classes` 轴的真实分辨率是两点，不是四点** —— `2/8/16` 三档在 **10/12 场**上
  类集合**逐元素相同**（不只个数相同）。⇒ 池的类集合相同 ⇒ 窗集合相同 ⇒
  `lda_fit` 输入逐位相同 ⇒ **输出逐位相同**（**算术恒等**，不是"实测差异很小"）。
  **画成 4 点曲线是假象。** 报告时合并成 `{2,8,16}` / `{32}` 两个配置。
- 两场例外**性质不同，不要混写**：`L_R003S01C02`（15/15/14，`2==8` 成立而 `8==16` **不**成立）、
  `S_R004S01C01`（15/13/13，`2≠8` 而 `8==16` 成立）
- **32 是唯一真正改变池的档位。判据必须用 `S2−S32`，不能用 `S16−S32`**：
  后者会把在 8/16 档已出局的类漏掉，误报成"每场只掉 1 个"。
  实测分布 **9 / 2 / 1**（掉 1/2/3 个类的场次）。
- 逐场 `|S16| == 16` 的有 **8/12** 场

**`M_R003C01:003-F`（19 窗）是 dev 类**（`M_R003C01 ∈ DEV_GROUPS`），
= `M_R003S02C01` 1 窗 + `M_R003S05C01` 18 窗。它是 32 档最常掉的那个类。

**"`classes` 轴只有两点分辨率"在 Task 5 产物上得到印证**（不是新结论，是旁证）：
`c2_cos_autok` / `c8_cos_autok` / `c16_cos_autok` 的归属错误率是
**9.1% / 9.2% / 9.4%**，逐场退化模式也一致（赢2/亏4/平6）；只有 `c32` 略有不同
（9.6%，赢3/亏5/平4）。**报告时不要画成 4 点曲线。**

**最差场的根因在选 K，不在上游**（2026-10-13 修正）：L_R003S01C02（基线 30.9%）
与 M_R003S04C01（基线 27.0%）是 dev 上最差的两场。**原始空间里就有合格的、
好得多的候选**：M_R003S04C01 当前选 K=3（26.96%），合格候选 K=7 是 **6.09%**；
L_R003S01C02 当前选 K=3（30.87%），合格候选 K=6 是 **4.94%**。

（早先这里写"最差场与后端无关，说明瓶颈在其上游"，依据是"四条 LDA 臂一动不动"。
**那是共享成分谬误**：两条臂共用同一个选择器，它们一致**恰恰不能**排除选择器。
一个共享成分导致两个变体一起失败，正是"问题在这个共享成分上"的证据，不是反证。）

**候选评分诊断（2026-10-13 二次修正，产物 v2，全部可复算）**：

- **完整逐场逐 K 表已补上**（`v13_candidate_score_table_dev.json`，12 场 × K=1..10 = 120 行），
  字段含 silhouette / objective / eligible / sizes / 实际细化簇数 / **句级四类**。
  旧产物只有汇总 ⇒ 当时任何数字都不可复算。

  **符号 = 评分越高、错误率越低**；中位数分割下高分组 6.08% vs 低分组 19.00%。
- **场内 ρ（选 K 真正依赖的）中位 −0.33**，远弱于跨场 −0.61；
  silhouette 的 argmax 命中最低错误率 **3/12**（含并列 4/12）。
- **λ=0.005 的影响是净值 +0.13 点**：4 场改变选择 —— 2 改善（共 +3.3 点）、
  1 变差（−1.8 点）、1 只改 K 不改错误率。
- **最大合格 K 在 dev 12/12 场都 = CAP=10** ⇒ "取最大合格 K"本身是常数。
- **新评分（细化后发言段稳定性）已证否**：两种门 0/12 场获胜，cap=8 下数值逐位不变。

  K=6 纯度 0.877/错误率 4.94%，**纯度排序与质量反序**。

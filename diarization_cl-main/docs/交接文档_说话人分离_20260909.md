## 2. 关键结论一:c1 在"正式 GT"上确实赢,但只有 3 个文件

用官方 `gt_ts.json` v3(唯一人工/半人工验证过的 GT,3 文件),collar0.5+trim:

| 文件 | 环境 | c1 | DSH 当前版 |
|---|---|---|---:|---:|
| 11842 | 1.5m 嘈杂 | 8.6% | **7.9%** |
| 11938 | 2m 嘈杂 | **8.5%** | 9.1% |
| 12220 | 1m 安静 | **2.3%** | 12.9% |
| **帧级合并** | | **5.7%** | **10.5%** |

- **方向与文本代理口径(250/373 vs 204/373)一致**,但 DER 口径下"不是全面碾压",而是:
  - c1 赢在 **fa(静音误报)低**(0.7% vs 6.9%);
  - c1 反而输在 **spk_err(边界处标签)高**(4.7% vs 3.3%)。
- **注意 11842 c1 输给了 DSH**(8.6% vs 7.9%),因为 c1 的短答细化在边界区引入 spk_err。**这提示下一步最值得优化的不是 fa(已很低),而是边界标签准确率。**

**这个结论的可信下限**:只有 3 个文件。要继续,必须扩到更多文件,但 §3 说明为什么扩不动。

## 3. 关键结论二(最重要,务必读):嘈杂档 GT 物理不可自动修

我花了全程大半精力修嘈杂 GT,撞到的是**物理墙**,不是算法墙。三个实测事实:

### 3.1 ASR 字级召回上限约 21%~26%
用 10657(嘈杂 2m)把 GT 文本钉到时间轴:

| 组合 | GT 字召回率 |
|---|---:|
| 原始音频 + SEACO（gt_ts_diag 现状） | 21% |
| 原始音频 + faster-whisper-large-v3 | 26% |
| **FRCRN 降噪 + faster-whisper** | **6.6%** |
| FRCRN 降噪 + SEACO | 21% |

- **换更强 ASR 只从 21%→26%,杯水车薪。**
- **降噪反而让召回跌到 6.6%**:因为 FRCRN 是为"保留近场说话人"训练的,**有意压制远场**,所以降噪后 2m 外的说话人被削得更弱。
- 这验证了"1m/2m 嘈杂那堵墙(如前 50/90)"的根源:**远场信号在原始音频里只剩 21%~26% 的可召回性,是前端物理极限,不是算法能救的。**

### 3.2 能量段在嘈杂档被噪声撑宽
`build_gt_auto.align_turns` 用"能量段"收紧 gap 轮边界。但嘈杂文件整段都有近场噪声能量 → gap 轮总能找到覆盖它的能量段 → 边界被拉宽到 3~7 秒。

### 3.3 gap 兜底有纯 bug(能修,但不解决根本)
`align_turns` 遇到连续多个 gap 轮夹在两个 asr 锚之间时,会把**每个 gap 轮的 start 都设成同一个值**(10657 尾部 4 轮全部 start=30.93),不单调、重叠。

**但即使修好这个 bug,3.1+3.2 仍在,嘈杂 GT 时间戳依然不可靠。** 我已用 proto_align_v2 尝试修,结果还是被能量段拉宽(见 §3.2)。

### 3.4 为什么 v3 那 3 个文件可信 = 恰好是安静档
`gt_ts.json` v3 = 11842(全 q=asr)、11938(仅 2 gap)、12220(7 gap 但无宽段)。**build_gt_auto 逻辑本身没坏,在安静档召回高(0.58~0.73)所以 produce 好 GT;在嘈杂档召回 21% 所以失败。**

### ❗结论(写进所有后续评估)
> **在单 mic + 2m 远场下,嘈杂档的逐字时间戳 GT 无法靠"自动 ASR 对齐 + 能量兜底"生成可信版本。要继续,只有两条路:(A) 人工听标嘈杂文件边界;(B) 只在安静档 VER 上做 DER 对比。** 在没做到之前,任何"嘈杂档 DER"结论**都不可信**,不要采信。

## 4. 关键结论三:DSH 前端输入口径很重要

- **DSH 生产前端是 FRCRN 降噪**(`web_server.py` denoise=auto,嘈杂档自动降噪)。
- 但 DSH 旧的 `output/a2ovl`(做 DER 用的)实际是 **raw 输入**——我用 `probe_dsh_input.py` 证实 raw 与当前版代码逐条一致(diff=0),而 frcrn 输入输出不同(gap2 0.067→0.048)。
- 所以**三文件 DER 里 c1 和 DSH 都是 raw 输入,口径是平权的**;但**生产实际是降噪后**,若要贴合生产,应两边都喂降噪音频(我测了 fair 对比:结论方向不变,c1 仍领先,但差距收窄——见 `der_ext_diag.json`)。

## 7. 本轮踩过的坑(避免重走)

- **不要用"整文件 ASR 召回"去修 GT**——撞墙,见 §3.1。

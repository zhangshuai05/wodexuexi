# AliMeeting 外部基准（单通道说话人日志）

本目录是 `diarization_cl` 主仓的**外部基准子项目**，目标只有一个：
把主仓的单通道说话人日志链路（VAD → 定窗 → CAM++ 嵌入 → 候选 K 选择聚类 → 句级归属）
搬到 **AliMeeting（ICASSP 2022 M2MeT）** 上跑一次可复现、可对照、口径写死的评测。

**这里不是竞赛参赛记录。** M2MeT 挑战赛 2022 年已结束，我们没有参赛，也没有榜单名次。
本目录产出的是"复现评测 + 误差归因"。

### 只用远场 ch0，不用近场

AliMeeting 同时提供 `Eval_Ali_far`（8 通道麦克风阵列）与 `Eval_Ali_near`
（每人一副耳机麦克风，每人一个文件）。**近场等于开卷考试**——每个通道只有
一位已知说话人，在其上做日志 DER 会接近 0，没有任何意义。

本目录**只使用远场**，并且只取 **ch0**（与主仓 README「本项目只读 ch0」一致），
通过 `prepare_ch0.py` 显式落成单声道派生文件，避免 8 通道在链路里被隐式 downmix。

## 2. TextGrid → RTTM 的口径（已验证）

转换规则：

```
语音段 = 某说话人 tier 中一段，若 "去掉所有 <...> 标记后剩余文本非空"
       （空文本 = 静音；纯标记如 <%> <#> <sil> <$> = 非语音）
说话人 = tier 名（如 N_SPK8013）
start  = xmin
duration = xmax - xmin
```

**这条规则不是猜的。** 用它转换 AISHELL-4 test 的 20 场 TextGrid，与主仓
`D:\yinp\AISHELL-4\data\test\TextGrid\*.rttm`（现行参考）**逐段完全一致 20/20**，
含时间戳与说话人标签。

> 中途发现的两个坑，都在这条规则里被覆盖：
> 1. 纯标记段（`<%>`、`<$>`）必须排除——否则 20 场里有 3 段是多余的。
> 2. 但**标记打头的真实语音段必须保留**：`<#>我我不我不是说这个<sil>` 这种，
>    按"整段是否以 `<` 开头"过滤会误杀，只有在剥掉标记后再判断才 20/20。

复现：

```bash
python textgrid_to_rttm.py --validate            # AISHELL-4: 期望 20/20
python textgrid_to_rttm.py --corpus alimeeting   # 生成 AliMeeting 参考 RTTM
```

## 3. 结果

数据：`Eval_Ali` 8 场远场，只取 **ch0 单声道**，md-eval union 分母，collar = 0.25。
所有数字由 `der.der()`（主仓）产出，机器可读结果在 `results/*.json`。

### 3.1 重叠难度标定（先做这一步）

| 语料 | 时长 | A 区域口径 | B 说话人-时间 | C 说话人重叠 |
|---|---|---|---|---|
| **AliMeeting Eval** 远场 | 3.88 h | **21.45%** | 25.98% | 47.43% |
| AISHELL-4 test 全部 20 场 | 11.51 h | 4.89% | 5.06% | 10.39% |
| AISHELL-4 **dev 12 场**（主仓实际口径） | 6.84 h | **5.09%** | 5.30% | 10.39% |

**AliMeeting 的重叠是 AISHELL-4 dev 的 4.21 倍**（+16.36 pts，A 区域口径）。
所以后面 DER 变差里有一部分是数据变难，**必须先做这个标定才能拆开**。

> ⚠️ **口径对不上官方声明值。** 官方文档说 Eval 平均重叠率 34.76%，但**没写明定义**。
> 本项目三种口径算出来是 21.45% / 25.98% / 47.43%，没有一个对得上（最近的是 B，还差 8.57 pts）。
> **不得**把本项目的数字与官方 34.76% 并列引用，也不得说"官方重叠率 34.76%，我们实测…"——
> 两者定义不同。要引用官方值就引官方值，要用我们的值就标明口径。
>
> 另：主仓 `der.py` 里那句注释「AISHELL-4 overlap is ~2% of speech」
> 与本项目实测（dev 12 场 A 口径 5.09% / B 口径 5.30%）差约 2.5 倍。两者定义未必相同，
> **存疑待查**，不要把任何一个当定论。

### 3.3 误差归因：confusion 来自重叠，但**不全是**

| 口径 | confusion 落在参考**重叠**帧 | 落在参考**单讲**帧 |
|---|---|---|
| 整场 | 13.55 pts | **16.53 pts** |
| 600 秒 | 11.13 pts | **14.71 pts** |

**一半以上的 confusion 发生在只有一个说话人的帧上** —— 那不是"重叠导致的必然错"，
是聚类本身把单讲段分错了。这否掉了"confusion 主要来自重叠天花板"这个直觉。

### 3.4 归因：误差到底卡在哪一环

`run_oracle_k.py` 三条腿**只有 K 不同**（同 VAD、同 CAM++、同 2.0 秒窗、
同边界公式、同 sliver 过滤、同评分器）。

| 场次 | 真值 K | auto K | auto DER | 强制真值 K 的 DER | 选 K 代价 |
|---|---|---|---|---|---|
| R8001_M8004 | 4 | 1 | 69.66% | 51.36% | +18.30 |
| R8003_M8001 | 4 | 3 | 36.38% | 36.32% | +0.06 |
| R8007_M8010 | 4 | 1 | 81.47% | 62.63% | +18.84 |
| R8007_M8011 | 4 | 2 | 40.66% | 27.11% | +13.55 |
| R8008_M8013 | 3 | 3 | 79.18% | 79.18% | +0.00 |
| R8009_M8018 | 2 | 2 | 12.07% | 12.07% | +0.00 |
| R8009_M8019 | 2 | 2 | 18.36% | 18.36% | +0.00 |
| R8009_M8020 | 2 | 2 | 8.90% | 8.90% | +0.00 |

| 分组 | auto DER | 真值 K DER | 选 K 命中 |
|---|---|---|---|
| 2 人场（3 场） | 13.11% | 13.11% | **3/3** |
| 3 人场（1 场） | 79.18% | 79.18% | 1/1 |
| 4 人场（4 场） | 57.04% | 44.35% | **0/4** |

**结论：给对人数（真值 K 上界）平均仍有 36.99% 的 DER，`auto` 与 `真值 K` 只差 6.34 pts。**
所以「K 选择是首要缺口」这个结论**不能跨语料迁移** —— 在 AliMeeting 上，主要瓶颈是聚类本身。

### 3.5 根因：候选准入是「整候选全否」，被 1–5 窗离群簇一票否决

`v11._candidate_clusters` 对每个 k 的候选做一次**全有或全无**的合格判定：

```python
eligible = (min(sizes) >= MIN_CLUSTER_WINDOWS       # = 4
            and min(sizes) / n >= MIN_CLUSTER_SHARE)  # = 0.015
score = _silhouette(E, labels) if eligible else -1.0
```

而 `_select_candidate` 在没有任何合格候选时直接返回 `candidates[0]`，**即 k=1**。

实测（`results/oracle_k_alimeeting_full.json` 的 `candidates` 字段）：

> **64/64 = 100%** 被否决的 k≥2 候选，否决原因都是"候选里含一个 size ≤ 5 的离群簇"。
> 没有一个是因轮廓系数低而被否。

最刺眼的两个例子：

```
R8007_M8011  真值4  窗数1850
  k=2  sizes=[518, 1332]            -> 合格，被选中
  k=4  sizes=[518, 921, 410, 1]     -> 否决   只因末尾那个 1 窗离群簇

R8007_M8010  真值4  窗数1851
  k=4  sizes=[1096, 752, 1, 2]      -> 否决   主簇 1096/752 其实已经分开了
  k=2  sizes=[1848, 3]              -> 否决
  -> 没有任何合格候选，返回 k=1，DER 81.47%
```

AHC 在任何 k 超过真值时必然切出 1–5 窗的离群簇，而准入门把这个离群簇的账算到
**整个候选**头上，于是系统只能退回 k=1。同样的门也作用于 0.6 秒 rescue 路径
（它复用 `_candidate_clusters` + `_select_candidate`），这解释了为什么
`R8001_M8004` / `R8007_M8010` 的 `level` 是 `2s-only` —— rescue 也没救回来。

> 这**证实了**主仓 README 里挂着未验证的那条假设：
> 「"份额门 `MIN_CLUSTER_SHARE` 是欠分割根因" —— 只是候选准入层面的观察。
> 改这道门能否修好欠分割未验证」。
> 但结论要往前推一步：**错的不是门限的数值，是"整候选全否"这个语义**。
> 把门限调低只会放进更多噪声候选；正确方向是先剔除/合并离群簇再判合格。
>
> ⚠️ **该修法未经验证。** 本子项目只定位根因，没有改算法。
> 任何"去掉离群簇就能把 DER 从 X 降到 Y"的说法目前**都是猜测**。

### 3.6 对照

#### A. 内部单变量对照（已跑完）

`run_baseline.py` 与 v12 **只差选 K 策略与边界细化**，其余全同。

| 臂 | DER | miss | FA | confusion | conf 重叠 | conf 单讲 |
|---|---|---|---|---|---|---|
| **v12 生产（穷举→门限+惩罚+0.6s 细化）** | **35.39%** | 1.60% | 3.72% | 30.08% | 13.55% | 16.53% |
| 穷举 K，无门限，无细化 | 39.14% | 10.53% | 3.60% | 25.01% | 12.32% | 12.69% |

**门限+惩罚+细化的净增益 = 3.75 pts**（35.39 vs 39.14）。

两条腿的误差结构不一样，值得注意：v12 把 **miss 从 10.53% 压到 1.60%**（细化把边界找回来了），
但 **confusion 从 25.01% 升到 30.08%**。单看 DER 会把这两个反向变化抵掉。

> ⚠️ 这个 arm **不是**主仓那条「22.79% 基线」。主仓探针腿用 `hop_s=0.5` 且不过滤碎段，
> 实测会让每个窗自成一段（窗间距 1.0 > 0.5×1.5），产出大量 1 窗碎段。
> 这里刻意对齐 v12 的分段规则以求得单变量，代价是**不能跟 22.79% 直接比**。

#### B. 外部对照：与 M2MeT 官方成绩的差距（已跑完）

官方成绩取自 arXiv:2202.03647（Summary）与 arXiv:2110.07393（M2MeT）。
**不是**用我们自己的尺子估的：本目录带了主办方的 `md-eval-22.pl`
（来自 <https://github.com/yufan-aslp/AliMeeting> 的 `speaker/dscore/`，Apache-2.0），
`md_eval_official.py` 用与 `dscore` 完全相同的调用方式跑它：

```
perl md-eval-22.pl -af -r ref.rttm -s sys.rttm -c <collar> -u <uem>
```

**同一批预测，两把尺子（8 场整场，跨文件汇总）：**

| 尺子 | collar 0.25 | collar 0 |
|---|---|---|
| **官基线 Eval-Ali-far** | **15.24%** | 24.52% |
| **我们 v12** | **33.09%** | 42.96% |
| 主仓 `der.py` 口径（同一批预测） | 35.39% | 45.66% |
| 我们（穷举 K 基线臂） | 38.86% | 47.78% |

**差距：**

| 对谁 | 分数 | 差距 | 倍数 |
|---|---|---|---|
| 官基线（ch0 单通道 + oracle VAD） | 15.24% | **+17.85 pts** | 2.17x |
| Royalflush 四系统融合（多通道） | 6.30% | +26.79 pts | 5.25x |
| 冠军 A41（多通道 + TS-VAD + 跳通道自注意力），Test 集 | 2.98% | +30.11 pts | 11.10x |

##### B.1 差距的真相：分档 + 三项分解

只看总分 15.24% vs 33.09% 会丢掉关键信息。md-eval 三项分解 × 按人数分档：

| 档 | 场数 | 官基线 | 我们 | 差距 | MISSED | FALARM | **SPKRERR** |
|---|---|---|---|---|---|---|---|
| 2 人 | 3 | 4.84% | **8.72%** | +3.88 (1.80x) | 4.52% | 4.03% | **0.18%** |
| 3 人 | 1 | 10.90% | 33.07% | +22.17 (3.03x) | 14.49% | 4.93% | **13.66%** |
| 4 人 | 4 | 23.18% | 48.63% | +25.45 (2.10x) | 20.91% | 2.57% | **25.14%** |
| 合计 | 8 | 15.24% | 33.09% | +17.85 (2.17x) | 14.52% | 3.40% | 15.16% |

对总差距的贡献（按 md-eval 计分说话人时间加权）：

| 档 | 对总差距贡献 | 占比 |
|---|---|---|
| 2 人 | +1.29 pts | **7%** |
| 3 人 | +3.29 pts | **18%** |
| 4 人 | +13.24 pts | **74%** |

**两个关键读数：**

1. **2 人会议上说话人认错率只有 0.18%**，几乎完美；那 8.72% 全部是
   MISSED 4.52% + FALARM 4.03%，即 **VAD 偏差**（官基线有 oracle SAD）。
   → 这一档的差距**不是算法问题**，要用 oracle-VAD 臂验证。
2. **3–4 人档 SPEAKER ERROR 达 13.66% / 25.14%**，且这两档合占差距的 **92%**。
   → 真正的算法问题集中在这里，而这里恰好就是 K 塌陷发生的地方
   （`auto K` 在 4 人档命中真值 **0/4**，8 场里 2 场塌成 k=1）。

> ⚠️ **更正**：本节早先写过"SPEAKER ERROR 15.16% ≈ 官基线整条 DER 15.24%，
> 所以在"谁说了哪句"上持平"。**那个说法是错的**。
> 官基线那 15.24% 里也含它自己的重叠型 MISSED，其 SPEAKER ERROR 必然低于 15.24%。
> 分档一看就清楚：2 人档我们确实远好于总体印象（0.18%），
> 但 3–4 人档的 13.66% / 25.14% 远高于基线总分。**总体是落后，不是持平。**

开 md-eval 的 `-1`（忽略参考重叠区）定位 MISSED 的来源：

| 臂 | 含重叠 | 忽略重叠 | 差 | MISSED 绝对量 |
|---|---|---|---|---|
| v12 | 33.09% | 24.15% | +8.94 pts | 1642.3s → 155.4s，**减少 91%** |
| 穷举K基线 | 38.86% | 30.87% | +7.99 pts | 2678.1s → 1060.1s |

> **14.52% 的 MISSED 里有 91% 来自重叠区。** 非重叠区 MISSED 只剩约 1.4%，
> 说明 VAD 本身不是问题。这是**单标签输出在多人同时说话时的结构天花板**，
> 即主仓 README 写的"单通道天花板：说话人重叠时单标签输出必然错一部分"。
> 现在"必然错一部分"第一次被量化：在本语料上约 **8.94 pts DER**。

⚠️ 官方**没有**开 `-1`，所以 24.15% 不是可引用的成绩，只是诊断。

##### B.2 必须一起声明的差异

1. **oracle VAD。** 主办方直接给参赛者 sentence segmentation（论文 §4.1：
   "we will provide segmentation timestamp to participants to obtain oracle SAD labels"）。
   官基线因此没有 VAD 误差；我们用自研 FSMN-VAD。**这一项补不了。**
2. **通道。** 官基线 `Ali-far` = 论文原文 *"we **selected the first channel** to obtain
   Ali-far"* → **就是 ch0 单通道**，与我们完全一致，**不存在差异**。
   但 Royalflush / 冠军 A41 是**多通道**（波束形成、跳通道自注意力），
   有空间信息，与我们不可直接比。
3. **Eval 集的近场泄漏。** Train/Eval 同时提供每人耳机麦克风音频+转录（只有 Test 集
   才只给远场 8 通道）。所以 Eval 上的分数可能用到了近场。多数论文写的是 far-field，
   但未逐篇核实。
4. **口径。** 已用官方脚本消除：我们的 `der.py` 给 35.39%，官方脚本给 33.09%，差 2.30 pts。

##### B.3 ⚠️ 由此发现主仓 `der.py` 的一处口径错误

`streaming_asr/der.py` 的 docstring 写着：

> "The denominator is the count of frames where the **reference has any speech**, counted
> once per frame however many speakers are active. ... **this is what md-eval does**, ...
> The spike's `der.py` counted `len(R)` ... so ... **its figures are not directly
> comparable to md-eval or pyannote**."

`md-eval-22.pl` 源码第 1967-1972 行：

```perl
$stats->{SCORED_SPEECH}  += $nref ? $seg_dur : 0;   # 并集口径
$stats->{SCORED_SPEAKER} += $seg_dur * $nref;       # <- 按活跃参考说话人数计权重
```

第 2414 行：`OVERALL SPEAKER DIARIZATION ERROR = ... / $scores->{SCORED_SPEAKER}`。

**md-eval 的分母就是按活跃说话人数计权重的（重叠帧算多次）**，正是 docstring 说"不可比"
的那一版。结论说反了。影响：主仓所有 DER 数字（含"22.79% 基线"）都在并集口径下，
与文献数字不可直接比。本语料上两者差 **2.30 pts**（35.39% vs 33.09%）。

> 建议把 `der.py` 的 docstring 改正，并在 README 的"不得引用的表述"表里加一条。
> 本子项目**没有**去改主仓代码（那是主仓的决定），只在此处记录。

> 这条腿现在是**可选的**：B 节已经给了外部对标（主办方官方脚本 + 论文成绩），
> pyannote 的增量价值只在于再添一个不同流派的对照。

## 4. 目录

> **数字归属**：本子项目不复制主仓的评分器与解析器，而是直接 import
> `streaming_asr/der.py` 与 `scripts/evaluation/probe_sentence_attribution.py`，
> 所以主仓一改，`results/` 下的数字就可能失效。
> `results/code_version.json` 记录了产出这批数字时的依赖哈希与算法常量，
> 结构变了用 `python pin_code_version.py --check` 一眼就能看出来。
> 本批数字对应的版本：`der.py b041b8eb`、`claude_a2_v11.py d794729f`、
> `claude_a2_v12.py 60ccbd77`（均在本次运行前定型，批次期间未变动）。

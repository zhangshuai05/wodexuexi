## 为什么叫 v8.1 而不是 v10

`v10`（`claude_a2_v10.py`）是"Paraformer 流式草稿 + v7 离线对照"的两遍实验，
它**不产生说话人标签**——标签是直接调 v7 拿的（逐段完全一致，已核）。
所以 v10 不是 v7 的升级版，改它也不会改分离效果。本次动的是它下面那一层。

## 改了什么

`claude_a2_v7_v8.py` 新增 `_c1_verdict()`，替换 `run_claude_lane` 里原来的：

```python
verdict, v_reasons = "reliable", []      # 无论分离成什么样
```

四条判据全部取自 v7 **自己 diag 里已经在算**的量，零新增计算：

| 判据 | 来源 |
|---|---|
| 算法按 `assumed_k` 人输出，实际只有 1 个"够重"的标签 | 输出标签的有效语音占比 |
| 段级路径判出塌缩 | `diag.collapsed` |
| 救援超出过切预算被弃用 | `diag.rescue_gate.passed` |
| 文本可疑 / 短段未解码 | `segment_contract` 的 flag（原本已算好） |

### 关键细节一：分母不能用输出的产物

`run_claude_lane` 里 `n_clusters = len(set(spk for spk in segs))` 是**按输出**算的。
那么真正只输出一个标签时 `n_clusters` 就是 1，`n_clusters >= 2` 这一支
**永远不触发**——最该报的那种形态反而溜过去。实测：

```
单标签输出 + n_clusters=1  →  reliable，理由为空
```

改成判据用 `assumed_k`（= `CLUST_N[0]`），`n_clusters` 只作输出侧证据记录，
diag 里两字段分开存。这一条是 PLAN_0917 §46 点出来的，我原版确实有这个洞。

### 关键细节二：占比按 VAD 有效语音，不按段跨度

段里含静音，用段跨度会把"很长的静音段"当成人。传了 `vsegs` 就只算被 VAD
覆盖的部分。构造用例：段跨度口径算 37% → 判够重；VAD 口径算 6.2% → 正确报不足。

### 关键细节三："够重"要同时满足两个条件

有效语音 ≥ `min_dur`(0.3s) **且** 占比 ≥ `min_share`(10%)。
只看时长会把 0657 那个 1.0s 孤立条目（占 6.6% 语音、不落在任何真值轮上）
当成"第二个人"，于是 `n_clusters=2` 看起来自洽——那正是塌缩的伪装。

## 试过并撤销的：带种子细化的过切门

`cluster_level == "dense_refine"`（用段级质心做种子、0.6s/0.15s 密集窗细化）
这条路径**原本没有门**。加了一版"候选切换数 > 段级基线 1.5 倍即判过切"，
然后撤销。两个理由：

1. **切换数不是判细化的量。** 细化的职责就是找换人点，它的切换数天然比段级多。
   拿"超过基线 1.5 倍"当判据，判的是任务目标本身。
2. **支持它的那次测量已作废。** 当时的对照是"门拦下 → 准确率掉 5.9pp"，
   但两次跑分别落在 23 段和 54 段——同一输入。见下节。

撤销后 `refine_switch_counts`（两个切换数）保留在 diag 里备查，**不参与判决**。
代码注释和测试里都不再引用任何百分比数字。

## FRCRN 在 GPU 上不确定（本轮最重要的环境事实）

同一份音频、同一份代码、连跑三次：

| 条件 | 分段数 |
|---|---|
| `denoise=auto`（走 FRCRN） | **23 / 23 / 54** |
| `denoise=off` | **31 / 31 / 31** |

FRCRN 两次输出实测 `max|Δ| = 3.05e-05`（相对 3.08e-05），在后续离散判决上被
放大成完全不同的分段。

**推论（影响后续所有实验）**：
- 不降噪时是确定的，所以"固定特征重跑聚类"这层能做干净对照。
- 只要经过 FRCRN，**同一输入跑两遍不能当对照**。任何含降噪的 A/B 必须固定
  降噪输出。
- 本轮一次基于"跑两遍"的对照（5.9pp）因此作废并删除。

## 2. v6：低置信碎段吸收

**触发**：用户报 `Note20260803112220.wav` 上"中间莫名其妙多出好几段"。

**定位**：截图来自 **c2 泳道 = v4**（`claude_a2_v4.py`），不是 c1。实测 v4 在 12220 上会裂出 0.15s 空文本微段（24.53-24.68 / 24.68-24.82）。但 v5 也没修干净。

**根因**：密集窗判决是**零门槛** `margin >= 0`。dump 311 个窗的边距发现：假碎段边距 **0.005~0.158**，正常段 **0.19~0.41**，差一个数量级。

**改法**：只吸收「时长 < 0.75s **且** 逐窗边距绝对值均值 < 0.18」的标签 run，并入边距更高的邻居。两个阈值参数化（`min_dur`/`weak_margin`）。

**受控 A/B**（同进程 + 同一份嵌入，三策略只差细化逻辑）：

|---|---:|---:|---:|

## 3. v7：救援过切门 + 单人崩溃修复

### 3.1 用户反馈的失分点
C(v6) 在 1m 文件上 28 段 vs 真值 16 轮，**过切 1.75×**；5 处碎段错标落在连续句内。D(v4) 更差，还有 7 个带标签的空段。

### 3.2 单人崩溃（确定性，不是偶发）
单说话人时 13 个滑窗嵌入相近 → 跳变阈值切不出边界 → `_build_seg` 只出 **1 个段代表** → `linkage` 拿到 1 个观测 → 抛：

```
ValueError: The number of observations cannot be determined on an empty distance matrix
```

真实入口 `run_claude_lane` 同样抛，前端该泳道显示 `error`。

**修**：`len(seg_reps) < 2` 时直接返回单说话人整段。9s 片段由崩溃变 1 段单人。

### 3.3 三个独立的过切/塌缩机制
全量扫描 23 文件后归类，之前只碰了最轻的一个：

| 机制 | 文件 | 症状 |
|---|---|---|
| 锚定路径低置信短 run | 11842/12220 | 残留碎段（v6 已修大部分）|
| **rescue 质心是噪声** | 10657/10836/10948/11741/11506 | **过切：62 次切换 vs 真值 18** |
| **`dom_max` 误挡** | 10228(dom .972)/11143(dom .967) | **整场塌缩 35/36、29/30** |

### 3.4 rescue 的真因（关键）
`_dense_rescue` 的远端质心 = "距主导质心最远的 30% 窗"。**在近单说话人音频里，那 30% 就是最难看的噪声窗**，于是造出一个"反噪声质心"（实测质心 cos 仅 **0.218**）。之后所有窗在"人声"和"反噪声"之间被二分，边距中位数 **+0.069 紧贴零轴**，序列反复穿零 → **每穿一次切一次换人**。

### 3.5 救援门（用户选"保留但大幅提高门槛"）
判据：救援输出切换数 > `window` 回退基线的 **`RESCUE_SWITCH_MAX=1.5`** 倍（且超出量 >2）即判过切、弃用救援。阈值由 7 文件实测扫描确定。

**踩坑（务必注意）**：第一版用**段级**标签序列（`lab_seg`，长度=段数 11~16）当 **window 级**基线。**两个量元素数不同、不可比**，导致基线被低估、门几乎无差别拒绝所有救援。修正为**在窗上重算** window 回退的切换数后，效果比预测还好。

## 4. 方法学修正：dense_rescue 旧结论不成立

项目记录写"c1+dense_rescue **256/373**，反超 DSH（243/373）"。这是**文本代理指标**（`compare_seaco.py`，SequenceMatcher 阈值 0.35）口径。

**问题**：该指标带运行噪声——**Fun-ASR-Nano 输出非确定性**，同一段音频两次解码文本可能不同（实测 12329 某段 `柠檬鸡爪` vs `柠檬冰茶`）。所以 **±几条差异不能当算法改进证据**。

**DER 口径重测**：救援在 DER 上不赚钱（39.68% vs 39.07%）。它长期未被发现，是因为**唯一可信的 3 文件 GT 恰好都不走救援**。

> ❗**规则**：要证明改进，用 DER（时间戳+说话人标签，不涉文本），或用同进程同嵌入的受控 A/B。**"文本 matched 涨了几条"不作为证据。**

## 5. 本轮新实测的两个事实

### 5.1 三个标准 k 选择判据在本特征空间全部失效
想修"说话人数写死为 2"，先测了标准手段（已知 2 人文件）：

| 判据 | 结果 | 原因 |
|---|---|---|
| 簇内平均相似度（阈值 0.75） | 全部退 k=1 | 真实 2 人文件簇内相似度仅 **0.48~0.56** |
| 最大两间隙 argmax | 选 k=3 | 段数一多，间隙系统性偏向更大 k |
| 簇内最大直径 | 4/5 文件退 k=1，12329 反给 k=3 | 直径随 k 单调下降，无判别性 |

根因：**CAM++ 对远端说话人的 within-person 余弦距离与 between-person 同量级**。任何绝对阈值型判据都不成立。

### 5.2 没有真实多人数据
23 个真值文件**全是 2 人**，3/4 人只能靠拼接合成（声学上不等价）。**多人结论只能标"合成样本上成立"。**

# 基线复算：22.79% 不可复现，而"选 K 代价 10.95 点"是我上一轮算错的

> 2026-09-22。给 v13 的 C 阶段定一个**口径明确**的起点。
> 尺子 = 仓库里的 `streaming_asr/der.py`（union 分母、collar 排除边界帧、贪心一对一映射；
> 14 个自检用例在 `streaming_asr/tests/test_der.py`，全绿）。
> 所有 RTTM 落盘可复算：`_v13_spike/work/{der_truek,probe_rederive,cache_probe,effk,selector_probe,cap_probe}/`。

## 0. 本文档自己勘误过一次

本文档的上一版结论是"**选 K 的代价是 10.95 个点，比交接文档勘误后的 5.11 大一倍，
C 阶段第一优先级 = 让选择器不选 k=1**"。

**那是错的。** 错因是拿**参考里的全部说话人**当"已知人数"的上界，而 AISHELL-4 的参考里有
大量**只说了几秒**的说话人。`L_R003S02C02` 报 gtK=6，其中 `004-M(2.0s)`、`003-F(5.7s)`、
`002-F(7.4s)` 三个加起来只占语音的 **2.9%**；`S_R004S03C01` 报 gtK=5 其实是**双人**会议。

按这个假上界算，任何选择器都必然"欠分割"、必然背上几十个点的"代价"。
**换成按有效人数（占语音 ≥5%）重算后，选 K 的净收益是 −0.01 个点**（§3）。
这个错误和交接文档 §0.1 记录的三次学费是同一类：**目标函数选错，算法再对也没用。**
教训写在这里而不是删掉，因为 §3 的表就是靠它才被读出来的。

## 1. 问题

交接文档 §4.3 与 `FINDINGS.md` §5 报的 v12 基线是

```
平均: der@selK=22.79%  der@trueK=21.98%  选K代价=0.81%
```

这条数字来自 `diag_der_truek.py`（16:49）→ `diag_der_sanity.py`（17:03）。
两条脚本和它们落盘的 RTTM 都还在；但 `_v13_spike/der.py` 在 **16:58** 被重写过

旧那个没留下。所以要先分清：**是尺子不同，还是取材不同。**

`M_R003S04C01`（51.11）和 `M_R003S05C01`（45.50）更像③（51.20 / 58.35），
其余 10 场更像①（16.60）。**也就是说，那 12 行不是同一条管线跑出来的。**

`S_R004S03C01` 的 1.1s 说话人都当成必须切出来的目标，才堆出来的。**删掉。**

### 3.2 唯一真实的一处：k=1 塌缩

`_select_candidate`（`claude_a2_v11.py:134-144`）在 `eligible` 为空或 `score <= 0` 时
返回 `candidates[0]`（k=1），**12 场里 2 场落进这个分支**，都走 `eligible 为空`：

- `L_R003S02C02`：k=2 是 `[7, 538]`——**聚类本身退化**，切不出第二个簇。选择器无过。
- `M_R003S04C01`：k=2 是 `[575, 1]`，而 **k=3 是 `[293, 282, 1]`——干净的二分，
  被一个孤立窗否决**。这条是选择器/判据的真实缺陷，值 **19.5 个点**（51.20 → 31.68）。

我验过两条退路，都**不成立**，写下来免得后面重走：

- **放松簇尺寸门槛到 min≥2**（`selector_probe/`）：只救回 `M_R003S04C01` 一小半，
  全 dev 均值 24.56% → 24.55%。**闸门不是尺寸。**
- **把候选 K 的上限从 4 放到 8**（`cap_probe/`）：平均连接在 k≥3 就不断吐单点窗
  （`M_R003S02C01`：k2 `[345,235]` → k3 最小簇 **1 窗**）。**闸门也不是上限**，
  是 `linkage(E,"average","cosine")` 在 AISHELL-4 上切不干净。

### 3.3 差距在"并人"，而并人算在 confusion，不是 FA

现行选择器在 dev 12 场的误差分解：

| | 均值 |
|---|---:|
| miss | **0.00%** |
| false alarm | **5.64%** |
| **confusion** | **18.92%** |
| DER | 24.56% |

**这直接推翻交接文档 §0.3 的第 3 条**："v12 在 12 场上 confusion 恒为 0，而 FA 高达 23%
—— 读 DER 表必须同时看 FA。"

那条**是旧评分器（multiplicity 分母）的产物**：旧口径下两个真人合一，映射把主导那位算匹配，
另一位进 FA，confusion 记 0。**换到 union 口径，同一批预测 confusion 是 18.92%、FA 只有 5.64%。**
`der.py` 的模块 docstring 第 2 条已经写了这个机制，但**没有人把它和"看表要看哪一列"连起来**。

后果：spike 时期所有"按 FA 读表"推出来的结论（包括"并人看不见"这个判断本身）
都是在对着一列被口径压成 0 的数字做诊断。**这一条要进边界报告。**

## 4. 对 v13 的含义

1. **不要引用 22.79%。** 它是两条管线的均值混合，逐场不可归因。可复算的是：
   **GT-VAD 取材 18.31%（现行 K）**、**缓存取材 24.56%（现行 K）**。两者都要报，
   并写明取材，因为差 6 个点全在取材上。
2. **C 阶段的瓶颈是聚类质量，不是选 K。** 误差里 confusion 占 18.92/24.56，
   miss 为 0，FA 只有 5.64%。**主战场是"把并在一起的人分开"，而它只出现在 confusion 列。**
3. **评分器固化这步已经做了**（`der.py` + 14 个用例）。它挡住的正是这次这种
   "两版实现给出不同孪生数字"的坑——§3.3 那条 FA/confusion 反转就是它抓出来的第一个。
4. **k=1 塌缩仍要修，但降级为"3.2 里那一条"**：只在 `[293,282,1]` 这种
   "有干净二分、被孤立窗否决"的形态上修，不要按尺寸门槛动刀（已验无效）。

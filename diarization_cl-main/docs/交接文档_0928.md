> 前置：先读 `交接文档_0924.md`（含 §11 续篇）。本文件是 2026-09-28 的续篇，
> **优先级高于 0924 的全部结论**——因为本轮发现的东西**推翻了 0924 §11.3 对 A 的评价基础**。

> 而 A/B 探针在 K=1..12 上评价规则。两者的假设空间不同，A@0.6 的 84.8% 不可迁移。**

## 0. 一句话现状

句子级主指标可用（`0924 §11.1`）。A/B 两个 K 候选在**探针上**跑完了 dev 12 场。
但 0928 发现：**探针与生产 `diarize` 的 K 空间不同**（探针 1..12，生产 1..4），
所以 A@0.6 的成绩**不能代表把 A 放进生产会得到的成绩**。
这个不等价**不是探针写错**，是**生产路径有一个从 v11 继承下来的活 bug**。

## 2. ★ 核心发现：生产路径的 K 上限恒为 4

### 2.1 事实

```python
# streaming_asr/claude_a2_v11.py:103
def _candidate_clusters(E, max_speakers=MAX_SPEAKERS):   # ← MAX_SPEAKERS 在 def 时绑定为 4
    for k in range(2, min(max_speakers, n) + 1):
```

```python
# streaming_asr/claude_a2_v12.py:175-186
with _v11_window_params(WIN_S, HOP_S, MAX_SPEAKERS):     # 把 v11.MAX_SPEAKERS 改成 10
    ...
    candidates, _ = v11._candidate_clusters(E)            # ← 不传 max_speakers！
```

`_v11_window_params` 改的是**模块级变量** `v11.MAX_SPEAKERS`，
但函数的默认值在 **`def` 执行时**（模块导入时）就绑定成了 `MAX_SPEAKERS` 的值 **4**，
改模块变量**不影响已绑定的默认值**。

### 2.2 定证

```
签名:            (E, max_speakers=4)
__defaults__:    (4,)
with 块内 v11.MAX_SPEAKERS = 10
       但 __defaults__ 仍是  (4,)          ← 不跟着变
不传参   → 候选 k=[1, 2, 3, 4]              ← 生产路径走这条
显式传10 → 候选 k=[1..10]                   ← 只有显式传才行
```

### 2.3 后果

1. **`diarize` 永远选不到 k>4。** 主窗 422 个窗上，`_candidate_clusters` 只造出
   `k=1,2,3,4` 四个候选（且 k=2,3,4 全是 `eligible=False`、`score=-1.0`，
   因为都有一个 1 窗的碎簇）——所以 `_select_candidate` **实际恒返回 k=1**。
2. **`forced_k=5` 静默失败**：找不到 k=5 的候选 → `next(..., None)` 是 None →
   跳过 → 落到 `eligible` 过滤 → 返回 `candidates[0]` = **k=1**。**不报错。**
3. **A/B 探针的 K 空间（1..12）与生产（1..4）不是同一个集合。**
   A@0.6 在 dev 12 场选的 k 是 **6–10（中位 9）**——**全部超出生产上限**。

### 2.4 这推翻了什么

- **0924 §11.3 对 A 的评价基础不成立。** 当时说"A 退化为按阈值间接选 K，
  6/12 场等于取最大 k"——那是**探针**的行为。把同样的 A 规则放进生产 `diarize`，
  任何 k>4 的候选都会被压到 k=1，成绩会掉到 base 附近甚至更差。
- **A@0.6 的 84.8% 不是"方法收益"，是"探针假设空间下的收益"。**
- 这把"三道串联锁"里的**第一把**（`cap` 在定义时绑定）确认**仍在生产路径上活着**——
  `0924 §4` 说三道锁"已修"，指的是 `unlocked_selector.build_unlocked` 那条线
  （它显式用 `cap=CAP` 循环，不受影响）。**但 `v12.diarize` 从未切换到解锁版选择器**，
  它仍调 `v11._candidate_clusters` + `v11._select_candidate`。

## 4. 我撤回的结论（0928 新增）

| 之前说过 | 为什么撤回 |
|---|---|
| "oracle 13.57 点"的可信度 | 它来自 `probe_ab_dev`（真模型 VAD 门），而我曾拿"全网格产物"（RTTM 门缓存路径）与之对比得出"+9.62、符号都能反"——**那两者连窗集都不同，对比无效**。13.57 本身是探针口径内的数字，仍成立，但**不能与任何缓存口径的数字并置**。 |
| "A 已否证" | **0928 更彻底地撤回**：不只是设计问题，探针的 K 空间与生产不同，A 的 84.8% 不构成对 A 的检验。 |

## 9. 方法论增补（补进 0924 §7）

- **"免费的 harness 自证"**：注入与基准**相同的参数**时，两条路径必须逐位相同。
  这一条不需要真值、不需要跑满 12 场，却能在几秒内证明 harness 无漂移。本轮靠它
  确认了缓存替换与 `forced_k` 注入没引入误差。
- **判据要比"成绩接近"严**：成绩接近可以是两处错误互相抵消。本轮要求**段表逐段、
  逐句预测逐句相同**。实测正是靠这条才发现"探针不做段合并"（22 倍段数差）——
  若只看成绩，这个差异会被"取最长重叠"完全吸收。
- **静默回退是最危险的失效模式**。`next((item for item in candidates if ...), None)`
  加一个"找不到就跳过"的分支，会让**注入失败表现为注入成功**。本轮的 `forced_k=5`
  就是这样。**凡是"找不到就回退"，都必须有断言。**
- **整数 `0` 是 falsy**（0924 已记）。本轮新增同族陷阱：**默认参数在 `def` 时绑定**。
  两者都属"看起来能变、其实不能变"。

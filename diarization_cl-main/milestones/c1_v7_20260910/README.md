# c1 v7 里程碑：2026-09-10

c1 说话人分离/识别版本，方法标识 `claude-a2-v7-c1`。本目录是独立归档；v4/v5/v6 与工作区、DSH 测试台的历史文件均保留。

## v7 变更

- **救援过切门**（本次主项）：`_dense_rescue` 的远端质心取自"距主导质心最远的 30% 窗"，在近单说话人音频里那批窗就是噪声，逐窗边距会在零轴附近反复穿越，切出大量假段。新增判据：救援输出切换数若超过 `window` 回退基线的 `RESCUE_SWITCH_MAX=1.5` 倍（且超出量 >2），判为过切并弃用救援。
- **基线必须同层级**：`window` 回退是在"窗"上聚类后合成连续段，基线不能用段级标签序列（长度=段数）充当，两者元素数不同、不可比。第一版实现犯了这个错，导致门几乎无差别拒绝所有救援，已修正。
- **单人崩溃修复**：段级只产出 1 个代表段时（整段语音被判成同一人），`linkage` 拿不到距离矩阵会抛 `ValueError`，真实入口 `run_claude_lane` 也因此崩。现在直接输出单说话人整段。
- 沿用 v6 的低置信碎段吸收与 v5 的稳定身份锚。

## 重要修正：dense_rescue 的旧结论不成立

项目记录曾写"c1+dense_rescue 256/373，反超 DSH"（文本代理指标）。本次在 DER 口径下重测：**救援机制在 DER 上不赚钱**（全开 39.68% vs 全关 39.07%，基本持平）。旧结论建立在文本代理指标上，而该指标带运行噪声（Fun-ASR-Nano 输出非确定性，同段音频两次解码文本可能不同）。救援的真实代价是制造大量假切换——它之所以长期未被发现，是因为唯一可信的 3 文件 GT 恰好都不走救援，救援的全部影响落在 DER 覆盖不到的盲区。

## 局限

- 全量仍有 57 处 <0.75s 短段，集中在 `Call20260718210454`（11）、`Note20260803111436`（11）等嘈杂文件。它们在锚定路径上，且**碎段边距（0.004~0.23）与正常段（0.02~0.35）范围重叠**，不存在干净阈值；这些文件无可信 GT，故本轮未处理。
- **`dom_max=0.95` 仍会挡掉真塌缩**：`Call20260718210228`（dom 0.972）与 `Note20260803111143`（dom 0.967）被判"近单说话人"而不给救援机会，输出 35/36、29/30 单一标签。这是 speaker-count 问题的表现，属下一轮范围。
- **说话人数仍写死为 2**；单人音频 ≥20s 仍会被判成 2 人（仅 9s 级短片段因守卫返回 1 人）。

嘈杂档自动 GT 漏标率高，DER 不可作为其优劣依据。
